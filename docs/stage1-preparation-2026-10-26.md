日期：2026-10-26。状态：**准备中，首版范围已确认，尚未实现或上线**。分支：`codex/stage1-preparation-20261026`，起点为阶段 0 Git 整理后的 `b2bb950`。

用户已选择：**先搜索、添加和研究默认池以外的沪深 A 股，再逐步开放模拟交易**。当前默认 200 只的交易能力保留；新增池外股票在首版由后端限制为研究用途，不能仅靠界面禁用下单按钮。

阶段 0 仍为进行中。Alembic 生产基线、备份/隔离恢复和 Git 归档已取得证据；告警最终验收、依赖锁定、最小 CI、真实回退及其他边界仍有未完成项。本次可以并行做需求与本地方案准备，不表示已经放行新的生产表结构。

## 1. 首版只打通一条流程

搜索池外沪深 A 股 → 查看证券身份及目录时间 → 添加到自己的自选/研究清单 → 显示行情准备状态 → 按需打开 K 线、财务和公告 → 用户主动发起已有单股研究 → 可移除自己的添加。

- 默认 200 只继续存在。每人最多添加 30 只池外股票，默认池内自选不占此配额，重复添加不重复计数。
- 首版只覆盖有可靠证券身份信息的沪深 A 股；北交所、港美股、ETF、基金、债券和存托凭证不混入 A 股结果。
- 能研究与能交易分开。证券类型、停复牌或特殊状态不明时如实显示，禁止据代码前缀推断为可交易；新增股票首版统一只读。
- 不把添加股票变成自动 AI 调用；不增加多轮研究、社交或排行榜功能。

## 2. 已核对的代码边界

| 入口 | 当前情况 | 实现时的影响 |
| --- | --- | --- |
| `backend/app/stock_pool.py`、`seed.py` | 固定默认池，新增缺失项，不删除旧数据；未取得行情用 0 占位 | 保留默认池，不用扩写常量来冒充全量目录 |
| `models.py:Stock` | 同时承载证券身份和最新报价，多项价格非空 | 证券目录与报价记录应分开；未准备好时不能伪造价格 |
| `api.py:list_stocks`、`get_stock` | 只查已入库且有有效价格的股票；无报价详情返回 503 | 目录搜索和准备状态需要独立返回，不能复用为全市场搜索 |
| `market/tick.py`、`history.py`、`status.py` | 行情轮询、历史补齐和覆盖率计算都遍历 `Stock` | 三处要使用统一的活跃范围，不能只改其中一处 |
| `models.py:WatchlistItem`、`api.py` 自选接口 | 已有账户与股票唯一关系，按账户隔离；每用户当前只有一个模拟账户 | 首版优先复用现有关系承载自定义研究添加，避免再维护重复订阅表 |
| `services/trading.py` | 交易检查已有行情时效和时段规则，尚无新增股票研究用途边界 | 新增池外股票的下单限制必须进入后端预览和提交路径 |
| `frontend/src/components/MarketMatrix.vue`、`useMarketData.ts` | 搜索是对已有行情列表的本地筛选，页面约 15 秒读取一次本地 API | 新增目录搜索需要独立入口；页面轮询不能变成外部数据抓取 |

直接把全市场目录写进现有 `stocks` 表，会同时扩大行情采集和历史补齐范围；这是本阶段首先需要避免的耦合。

## 3. 采用轻量方案，复用现有数据

**证券目录**只保存身份信息：交易所、代码、名称、证券类型、可核实的板块/状态、来源和采集时间。建议新增独立目录模型；字段、索引与更新方式在第一步小样本核验后定稿。目录按低频快照更新，搜索读取本地目录，不按用户每次输入去请求第三方。

**用户添加**先复用 `watchlist_items`。搜索后点击“添加”即加入自选/研究清单；删除该自选释放本人的池外配额。这样用户只有一个添加入口，也只有一份成员关系。原规划的独立 `user_stock_subscriptions` 暂不直接照建；以后确有“研究清单与收藏分离”的需求再迁移。

**全站活跃范围**统一为：默认池 ∪ 全体有效账户的自选 ∪ 仍有数量的持仓 ∪ 未结委托引用，按证券去重。取消添加只移除自己的关系，不删除公开缓存、持仓或交易历史；最后一个用户移除也先检查持仓和委托保留条件。普通用户的页面仍以默认池及自己的自选/持仓为范围，不暴露其他用户的添加关系。

**准备状态**先根据报价及已有行情/公告等缓存和同步记录汇总，区分“正在准备、可查看、部分缺失、失败可重试”。不为第一版额外引入 Redis、消息队列或多个后台执行者；只有持久化重试确有需要时，再决定是否增加 `stock_activity_states`。

约 20 名测试用户、每人 30 只池外股票时，200 + 20 × 30 = 800 是未去重且不含持仓/委托额外保留项的规模估计，不是已经验证的容量。要测批次数、每轮耗时、失败退避和覆盖率，不能直接保证 5 分钟全量刷新成功。

## 4. 分步推进

### 第一步：验证证券目录，暂不改业务表

- 目标：证明可以可靠识别池外沪深 A 股，并保留来源、快照时间和未知项。
- 主要文件（计划）：`services/security_catalog.py`、目录解析样本、`tests/test_security_catalog.py`；不改默认池。
- 操作：核定数据来源/可持续获取方式；以可追溯的小样本做代码前导零、市场和证券类型解析，加入失效/异常样本。搜索按代码精确优先、名称匹配其次，限制查询长度及返回数量。
- 完成信号：同一快照可重复解析；A 股与非支持类型能区分；源失败保留上一份完整快照并显示时间，未知状态不编造。

### 第二步：目录入库、添加配额与研究用途约束

- 目标：一名用户能在 30 只池外配额内添加/移除，旧账户和默认池继续工作。
- 主要文件（计划）：`models.py`、新增 Alembic revision、目录/自选服务、`api.py`、`schemas.py`、`trading.py` 及相关测试。
- 操作：先确定新增目录表的唯一约束和索引；使用新增迁移，不改 `20261018_01` 冻结基线；复用自选接口，事务内串行校验配额，处理并发添加同一股票及第 30/31 只的竞争；股票实体和底层缓存全站只建一份。
- 接口方向：新增 `GET /api/securities/search`，避免与既有 `/stocks/{symbol}` 路由冲突；保留自选增删接口，补充目录身份和准备状态返回。接口与字段仍需在实现时定稿。
- 完成信号：重复添加幂等、并发不超额、两用户各自隔离；直接调用订单预览/提交也无法买入新增池外股票；默认池内原有行为不被统一禁用。

### 第三步：共享活跃池与渐进取数

- 目标：同一股票只采集/缓存一份，添加成功不等待全部外部数据返回。
- 主要文件（计划）：`services/stock_activity.py`、`market/tick.py`、`history.py`、`status.py`、已有财务/公告服务。
- 操作：统一活跃股票选择器，用于报价刷新、历史补齐和覆盖率；添加后的首次抓取排入单执行者任务，合并重复需求；行情先到，K 线随后，财务和公告在查看时加载；限制单轮预算和失败重试。
- 完成信号：添加/移除会改变应刷新集合，保留项不会被错误移除；一只股票失败不拖住其他股票；覆盖率分母不包含整个证券目录；缺失价格和数据时间显示清楚。

### 第四步：前端打通研究流程

- 目标：用户可发现池外股票、添加并看到分项准备情况。
- 主要文件（计划）：`MarketMatrix.vue`、`StockDetailsDrawer.vue`、`StockAnalysisWorkspace.vue`、自选 composable、`api.ts`、`types.ts` 及前端回归。
- 操作：搜索保留当前列表筛选，同时提供“搜索更多沪深股票”；展示已添加数量、准备状态和错误重试；新增股票显示“仅研究”；旧请求返回不能覆盖新搜索或已切换会话。
- 完成信号：没有报价时证券仍可发现，其他信息可按需查看；研究页面与委托区域清晰区分，用户不会把 0 当成真实报价。

### 第五步：验收和生产候选

- 目标：新流程通过回归及真实数据库迁移核验后，才准备生产发布。
- 操作：运行新增目录/配额/活跃池/权限测试、现有交易回归、前端测试与构建；在隔离 MySQL 验证旧版本到新 head，核对原账户、现金、持仓、订单和成交；在受限真实源样本上验证获取与时效。SQLite 和命令替身不能代替这一步。
- 完成信号：默认池旧功能通过；并发 30/31 配额、多用户共享缓存、移除保留项、外部失败降级、直接接口绕过限制等关键场景通过，记录证据及未覆盖项。
